## 3. Frozen interfaces

F1 Host command resolution (both runtimes, identical rule, every target). `resolve(name)` scans
only the entries of PATH, in order, never the current directory. A PATH entry wrapped in double
quotes has the quotes stripped; empty entries are skipped. Search order is cmd.exe's: for each
directory in turn, the extensions in PATHEXT order. On win32 the candidate extensions are the
members of PATHEXT (default `.COM;.EXE;.BAT;.CMD`) that are also in {`.com`,`.exe`,`.bat`,`.cmd`},
compared case-insensitively; other PATHEXT members (`.ps1`, `.js`, `.vbs`) are not launchable and
are skipped. Elsewhere the name must be an executable file. Returns the full path or none.
`detect()` is `resolve(name) is not none`, so detect and launch agree.
Detection interface (frozen, I-2): the same rule serves all four targets (claude, codex, copilot,
gemini) and `--target auto` / `runtime_detected` in both runtimes. No adapter or auto-detection
path calls `shutil.which`, or Node's old `commandExists`/PATHEXT scan, directly; Python's four
adapters and Node's `commandExists`/`detectTarget` all go through `resolve`. Only copilot and
gemini are launched (discovery); claude and codex are detected only.

F2 Host launch (no `shell=True`, no string building from variable parts). The argument list is
always the constant vector: copilot `skill list --json`; gemini `skills list`.
- Not win32, or the resolved path ends in `.exe`/`.com`: run the resolved path directly.
- win32 and `.cmd`/`.bat`: Python runs the resolved path as argv[0] of a list (CreateProcess
  runs a `.cmd` given by full path; verified on Python 3.13). Node cannot (spawnSync of a
  `.cmd` fails with EINVAL since the 2024 libuv fix, verified on Node 24), so Node runs
  `process.env.ComSpec` (fallback `%SystemRoot%\System32\cmd.exe`, never the bare name, which
  libuv would search in the cwd first) with `['/d','/v:off','/s','/c', '""<path>" <args>"']` and
  `windowsVerbatimArguments: true` (verified with a shim in a directory containing a space; `/v:off`
  not yet probed, C2 proves it). `ComSpec` is trusted environment, the same trust as PATH.
- Refusal set (frozen, one set, identical in both runtimes): a resolved `.cmd`/`.bat` path that
  contains any of `" % & | < > ^ ! ( ) , ; =` or a CR or LF is detected but not launchable. Python
  needs the whole set because `list2cmdline` quotes argv[0] only when it holds a space or tab, so a
  space-free path reaches the implicit `cmd.exe /c` bare (measured: `a&b\copilot.cmd` ran a decoy at
  `b\copilot.cmd`; `^` and `(` broke the command). Node's quoted route is safe for `& ^ ( ) !`
  (measured) but uses the same set so both installers give the same result. It is a pure function in
  each runtime (Python `unsafe_shim_path(path)`, Node `unsafeShimPath(path)`) returning the first
  offending character or none; the launch returns `state: failed` with evidence
  `unsafe host command path: <path> (character <c>)`, and no process is started. `detect()` stays
  true (the host is present). Paths ending `.exe`/`.com` are not run through cmd.exe and are not
  subject to the set. This closes the injection surface by refusal; a user whose npm prefix
  contains such a character gets the diagnostic instead of a launch.
- Spawn timeout stays 30 s. Evidence tuples keep their present shape (`exit=...`, stdout, stderr);
  an OSError or ENOENT still yields `state: failed`.

F3 Post-commit cleanup (I2). The commit point is the line after `inject("after-receipt")`.
From there, removal of the backup is best effort: a failure does not roll back and does not
raise. `install_skill` / `installSkill` returns `state: installed` and adds
`warnings: ["backup cleanup failed: <message>; remove <backup path> by hand"]` only when
cleanup failed (key absent otherwise). The `finally` backup removal is also best effort. A new
injection point `cleanup-backup` fires immediately before the backup removal, inside the
best-effort region, so tests can fail the removal without monkeypatching. A leftover backup is
then reported by `verify` as `no_backup_leftovers: false`, which is the honest signal.

F4 Receipt read (I3). One helper in each runtime returns the receipt as an object or raises
InstallError / InstallerError with message `invalid installation receipt: <reason>`. A receipt
that is not a JSON object, or whose `payload_hashes` / `document_status` / `host_discovery` is
present with the wrong type, is invalid. install, verify and uninstall exit 2 with
`state: failed` (verify: `passed: false`) and no traceback or raw TypeError text.

F5 Blocked profile (I4). Node `install` with `document_status.state != "ready"` returns exit 2,
`{"state":"blocked","document_status":{...,"action":[...]},"mutation_performed":false}`, the
same keys as the Python CLI at installer/install.py:87-97; `command` may be added. Parity
tests compare `state`, exit code, `document_status.action`, and (failed results) presence of
`error`; they do not compare message wording.

## 7. Risks and open questions for the controller

- The Windows route was probed here (Node 24.16, Python 3.13.3) with a `.cmd` in a directory with a
  space; both worked. Only Windows CI proves other Node majors (20, 22): the C2 real-process test
  must run in CI on Windows with Node 20/22/24 before landing.
- The F2 cmd.exe route is safe only because the argument vector is constant and the path passes the
  refusal set. A future change that passes variable arguments to a host must not reuse it without
  quoting rules; C2 puts a comment at the helper saying so. If Node 20/22 Windows CI fails the
  cmd.exe route, the documented fallback is "detected but unverifiable" for `.cmd` hosts (state not
  verified, evidence says why), decided by the controller.
- Python's `subprocess` on a `.cmd` relies on CreateProcess's implicit cmd.exe; if a Python build ever
  stops doing that, C1's real-process test fails loudly (it is the guard for this).
- F3 changes the install result by adding an optional `warnings` key. It is additive; old consumers keep
  working (AGENTS.md published-contract rule). The CHANGELOG line for it belongs to PR D.
- C6 mutation check edits `_managed_path` temporarily; the implementer must revert it (report shows the
  clean `git diff --stat`).
- Wave 1 has 5 agents on tests plus two adapter rewrites; if the controller wants fewer, C8 and C7 can
  trail C1/C2 without changing any file ownership.
