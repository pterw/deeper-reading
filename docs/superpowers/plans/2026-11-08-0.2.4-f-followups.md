# Plan F: 0.2.4 follow-ups (verifier dod.json clearing, linear verifier loops, Windows pack-smoke launch)

Base: main a8d27ac (PR#11 merged). Branch `fix/0.2.4-followups` from main. Ships before the 0.2.4 tag (the release is not a task).
Rules: AGENTS.md. Rulings: R43, R44, R53 (context.md of the 0.2.4 train workspace). Evidence for task 2:
`.superpowers/sdd/2026-11-07-train-0.2.4/review-M-siblings.md`, sections S8 and S9.

## 1. Goal

Three small, separately committed changes. (1) The verifier removes any old `dod.json` before it validates, so
an interrupted or failed write leaves no stale passing file. (2) Two quadratic loops in `scripts/verify_run.py`
become linear (a 20,000-chunk run took 90 s). (3) The Windows pack-smoke test stops using `shell: true`
(Node DEP0190) and launches `.cmd` files through `cmd.exe`. Closes: R43, R53 (S8, S9), R44.

## 2. Not in scope

- S10 (`chunk_view.chunk_media` filter per chunk): not named by R53; separate PR.
- Any change to verdicts, finding codes or messages; `script_io.py` and the installers' `launchHost` are unchanged.
- A new finding code for a `dod.json` that is a directory (see section 7).

## 3. Frozen interfaces

- `dod.json` location and shape unchanged: `<run-root>/dod.json`, written atomically by `script_io.write_text_atomic`.
  The exit code of `verify_run.py` stays authoritative (0 only when `passed`).
- R43 placement (controller ruling, round 1): in `verify_run.main` (:1307) the delete runs right after
  `validate_output(canonical_dod, inputs=[ledger], root=run_root)` (:1316) and BEFORE the `--write-dod` mismatch
  check (:1317-1319), so no exit-1 path leaves a stale passing `dod.json`.
  Reason for "after validate_output": it rejects a symlink `dod.json`, a path outside the run root and a ledger that
  is itself named `dod.json`; deleting before it would follow or destroy exactly those. If `validate_output` itself
  raises, nothing was deleted, and none of those cases is a regular stale passing file.
- `_node_is_resolved(events, node)` (:798) may be replaced; no test imports it (grep before removing it).
- Finding codes, predicates and messages emitted by `_validate_findings` are byte-identical before and after.

## 4. Tasks

Tasks 1 and 2 both edit `scripts/verify_run.py`, so they are serial (same file, task 2 after task 1). Task 3 touches
no shared file and is independent. The owner reads the `verify_run.py` diff before merge (AGENTS.md; R43, R53).
All three tasks are code tasks, so their Mode is `code` (parallel code phase, then landing).

**T1 validation clears dod.json (R43)** | Wave 1 | After: none | Mode: code
Touches: scripts/verify_run.py, tests/test_verify_run.py, tests/test_script_hardening.py, CHANGELOG.md
Immediately after `validate_output(...)` (:1316) and before the `--write-dod` check (:1317-1319), call
`canonical_dod.unlink(missing_ok=True)` (see section 3). A `dod.json` that is a symlink is already refused by
`validate_output` (exit 1 through `run_cli`, "output must not be a symbolic link"), so it is never followed or
removed. A `dod.json` that is a directory makes `unlink` raise (`IsADirectoryError` or `PermissionError`); `run_cli`
turns that into `FAIL:` and exit 1, the existing error convention (no new finding). The normal write at :1347 stays
`write_text_atomic`.
Tests (extend, no near-duplicates). In-process `main` tests must set `sys.argv` (monkeypatch it to the argv list
`main` parses with argparse, :1307-1312) before calling `main()`:
- in test_verify_run.py: a stale passing `dod.json` next to a valid ledger whose write fails (monkeypatch
  `write_text_atomic` in the module to raise, call `main` in-process) leaves no `dod.json`. This is the test that
  goes red when the unlink is deleted.
- in test_verify_run.py: a stale passing `dod.json` plus a `--write-dod` path that mismatches the canonical one
  (exit 1 at :1317-1319) leaves no `dod.json`. This goes red when the unlink sits after that check.
- in test_verify_run.py: a stale passing `dod.json` with a failing ledger (CLI run, `"[]"` as in :235) ends with a
  `dod.json` holding `passed: false`. This documents R43's reading (a failing validation still writes a failing
  file); it is a behaviour pin, not a mutation guard (`os.replace` would overwrite the stale file anyway).
- in test_verify_run.py: `dod.json` is a directory: exit 1, `FAIL:` on stderr, the directory still exists.
- in test_script_hardening.py: extend `test_verifier_rejects_dod_symlink` (:107) to assert the link still exists
  and still points at `outside.txt` (the hostile case: the symlink is not followed or deleted). It needs symlink
  privilege; the existing test already skips on `OSError`.
CHANGELOG (Unreleased): "The verifier deletes an existing `dod.json` before it validates, so an interrupted or
failed run no longer leaves a stale passing file."
Accept: `python -m pytest tests/test_verify_run.py tests/test_script_hardening.py -q`. Mutations: move the unlink
before `validate_output` (the symlink test goes red); delete it (the write-failure test goes red); move it after the
`--write-dod` check (the mismatch test goes red).

**T2 linear node and chunk-id checks (R53)** | Wave 2 | After: T1 | Mode: code
Touches: scripts/verify_run.py, tests/test_verify_run.py, CHANGELOG.md
S8: build the resolved-node set once from `events[:done_i]` (events of type `node_passed` or `node_superseded`),
and test each plan node against it at the loop at :1166. Only string `node` values go in the set, because the old
code compared `e.get("node") == str(node)`; an unhashable `node` in an event must not raise (that would turn into
`ledger.validation.error`).
S9: at :1011-1027 use sets for the two membership tests (`verified_event_ids`, `manifest_chunk_ids`); keep the lists
for the duplicate, order and mirror checks, and iterate the lists so finding order is unchanged.
Tests: timing tests isolate the two loops; they do not run the full pipeline. `tests/run_fixture.py` `valid_run`
asserts exactly one chunk and the real multi-chunk builder (`tests/test_anti_skimming_ledger.py` `valid_run(...,
chunk_count=N)`) would run extraction and per-chunk evidence for 20,000 chunks (about 6 s even after both fixes,
per review-M-siblings.md), so neither is used for the timing bound. Instead, call `_validate_findings` on a
synthetic run dict, with `_validate_chunk_evidence` monkeypatched to return fixed values:
- S8 case: a plan of 20,000 nodes and events (`node_passed` per node, `verification_started`,
  `verification_passed`, `done`); no chunking section needed. Assert no `done.node.unresolved` finding.
- S9 case: `_validate_chunk_evidence` patched to return 20,000 manifest chunk ids, with 20,000 matching
  `chunk_verified` events in order. Assert no `events.chunk_verified.missing`, `.unknown`, `.duplicate` or `.order`
  finding.
The implementer reads `_validate_findings` (:816) and the `_validate_chunk_evidence` return shape (:300) and writes
the smallest dict that reaches those loops; if a pure helper is extracted for either loop, test it directly too.
Bound: each case asserts under 3 s (a few seconds, not tight). The implementer must report measured before/after
times at 20,000 (expected: tens of seconds before for each case, well under 1 s after), and the chosen size must
make the pre-fix code exceed the bound. The existing verifier tests and parity tests stay unchanged and green, and
one existing unresolved-node case still yields the same code and message.
CHANGELOG: one line only if kept: "Verification of very large runs (tens of thousands of chunks) is much faster."
Accept: `python -m pytest tests/test_verify_run.py tests/test_verify_run_parity.py tests/test_verify_media.py -q`;
mutate by restoring the per-node scan (S8 timing case red) and the list membership tests (S9 timing case red).

**T3 pack-smoke launches .cmd without a shell (R44)** | Wave 1 | After: none | Mode: code
Touches: tests/npm/npm-pack-smoke.test.js
In `run()` (:30-39) drop `shell: process.platform === "win32"`. On win32, when the command ends in `.cmd` or
`.bat`, run `process.env.ComSpec` (fallback `System32\cmd.exe` under `SystemRoot`) with
`["/d", "/v:off", "/s", "/c", line]` and `windowsVerbatimArguments: true`, where `line` is
`""<command>" "<arg>" ..."` (outer quotes for `/s`, each argument double-quoted). This is the installer's frozen
rule F2 (`launchHost`, `installer/node/adapters.js:100-110`); that function is private and its comment says it is
safe only for constant arguments, so the test keeps its own small quoting helper rather than importing it. Here the
arguments include the sandbox paths, so every argument is quoted. Note: cmd.exe still expands `%VAR%` inside double
quotes even with `/v:off`; the temp-path prefix is controlled by the test, so this is only a note. Other platforms
call `spawnSync` directly.
The sandbox directory (`mkdtempSync` at :42) gets a space in its prefix (`"deeper-reading pack-"`), so the test
runs from a path containing a space on every platform. Callers (`npmCommand`, `npxCommand`, the installed
`deeper-reading.cmd`) are unchanged.
Accept: `npm run test:pack-smoke` exits 0 on Windows; the one DEP0190 check is
`node --throw-deprecation --test tests/npm/npm-pack-smoke.test.js` (exit 0, no DEP0190 in the output). Planted
defect (T3 mutation): drop the argument quoting in the helper; on Windows the test must go red because the install
`--prefix` path contains a space. No CHANGELOG line (test only).

  (no stale passing file when the write fails or the process dies). Confirm that reading.

  (pinned by a T1 test).

  (matrix ubuntu-latest and windows-latest, Node 20/22/24) runs `npm run test:pack-smoke` as its own step (:128-129)
