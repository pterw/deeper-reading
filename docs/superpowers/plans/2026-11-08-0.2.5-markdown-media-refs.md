## 3. Frozen interfaces

- F1 order, exactly: `html.unescape(destination)`, then split on `[?#]` (first occurrence), then the lower-cased
  extension test against `_IMAGE_EXTENSIONS`. The recorded `ref` keeps the ORIGINAL spelling (`plot&#46;png`), never the
  decoded one. Why decode-then-split: a literal `#` in a file name is written `%23` in CommonMark, so a `#` that survives
  decoding (including one produced by `&#35;` or `&num;`) is a real fragment delimiter; splitting first would read the
  `#` of a numeric reference as a fragment and cut `plot&#46;png` to `plot&`.
- F2 behaviour: the attribute lookup used by `_attr` callers (:277-281: src, data-src, alt, class) tokenizes the raw tag
  with `html.parser.HTMLParser` the way `scripts/extract_html.py` does (`convert_charrefs=True`; `_record_media`,
  extract_html.py:55-57 builds `{name.lower(): value}`, so for a duplicate name the LAST one wins). Each tag is
  tokenized once and all four attributes are read from that one parse. An attribute name inside another attribute's
  quoted value is never matched. Names compare case-insensitively. Callers keep their `or` fallbacks (`src` then
  `data-src`; `class` split on whitespace for `mermaid`).
- Unterminated tags: existing MEDIA_ROWS lines 148, 151 and 153 (`<img alt="x>`, `<img src="a.png" alt="x>`) keep their
  expected tuples. When HTMLParser yields no start-tag event, the lookup falls back to the old whole-tag regex result,
  identical on Python 3.10-3.13 (HTMLParser's handling of unterminated tags differs across patch releases).
- R52 fail-toward-recording: where the new code cannot decide, it records the reference, as before. An extra record costs
  a not_read disposition; a missed one passes verification unseen. In particular a destination whose character
  reference cannot be decoded (a decimal reference over 4300 digits raises ValueError on 3.11+) does not abort
  extraction: `_is_image_target` catches it and records the reference.
