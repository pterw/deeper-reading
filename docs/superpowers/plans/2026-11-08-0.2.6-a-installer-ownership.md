# 0.2.6 Plan A: Installer Ownership and Recovery (#26, #27) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A link anywhere in a skill path must never let one target or project verify, install over or uninstall another's install (#26). When a receipt is missing, both installers' refusals name the way back, and the README says which install route is supported (#27). Python and Node change together. Closes #26 and #27 in milestone 0.2.6.

**Architecture:** Two shared case tables (ownership and recovery) are frozen first, in one data task. Each installer then runs the same table in its own new test file, so Python and Node go red then green on their own files, and a difference between installers fails a test. The ownership guard lives at the command-line layer of both installers (R67): Python `command_*` in `installer/install.py`, Node `resolveContext` in `installer/node/cli.js`. The recovery text sits in the two core refusals. The tasks are sliced by installer, so each runs as a parallel code phase; the slices of one behaviour change land together as one commit (R86, AGENTS.md line 203).

**Tech Stack:** Python 3.10-3.13 standard library and pytest; Node 24 `node:test`; JSON fixtures under `tests/fixtures`.

## Global Constraints

- Python and Node installers change together (AGENTS.md line 203): a behaviour change in one lands with the other in one commit. Parallel slices do not break this: the Dispatch section names the landing groups.
- Standard library only in tests and installers. LF files. Edit and Write tools only; never `sed -i`.
- Tests assert intended behaviour and would fail if it broke; one test per behaviour, near-duplicates parametrized; no wording pins where a stable code exists. A new test file runs the shared case table; it adds no case of its own beyond what its task names.
- Real command-line calls only: the tests start `python installer/install.py` and `node installer/node/cli.js` in a throwaway home (`HOME` and `USERPROFILE` set to a temp folder). Tests never touch the real home or the real `~/.claude` or `~/.agents`.
- No skip: a link is a junction on Windows (`_winapi.CreateJunction` in Python, `fs.symlinkSync(target, link, "junction")` in Node) and a directory symlink elsewhere. `tests/check_skip_budget.py` fails unbudgeted skips.
- Nothing new ships: `tests/mutants/` is test-only and not in any ship list; no new installer module, no ship-list change, no `VERSION` or `release.yml` change, no receipt field (R69). The guard and the recovery text are edits to existing installer files.
- Code phases run focused tests only (R98): the test files a task writes or changes and the existing ones that import a changed module. The full `pytest` and `npm test` run in the nested gate-run and at landing. No step plants a defect by hand (R97): the committed mutants file (A7) and the reviewer's scratch `mutate.py` file do that job. Mutation probes run only in a scratch copy of the repository, never with cwd in the repository. No disk-wide searches.
- Commit subjects are conventional; no attribution lines; merge commits only; never `--amend`, rebase, reset or `--no-verify`. A task is about 5 minutes of agent work; code phases never commit, the controller lands each reviewed group.
- A commit or changelog claim states only what the diff does.

## Frozen interfaces

### Ownership rule

Rules R65, R66, R68, R69 and R78. Run by `install` (including `--dry-run`), `verify` and `uninstall` after the target is resolved (`auto` is already a concrete name) and before the core call, and before the document-profile check in both installers. `doctor` is not guarded. Steps, first hit wins:

1. No receipt file at the resolved folder: no guard; the core keeps its existing missing-receipt handling. A receipt that is unreadable or not a JSON object: no guard; the core's existing `invalid installation receipt` error stands.
2. Receipt `target` is not a known adapter name or `scope` is not `user`/`project`: refuse `installer.receipt.owner_invalid`. Message says the recovery is deleting the folder (also for `uninstall`), with the delete wording of the recovery text below.
3. Owner root = the adapter root for the receipt's `target` and `scope`, computed unresolved with the request's home (lexical, as the adapters do today). Differs from the request's unresolved root: refuse `installer.owner.mismatch`. Message names the owning target and scope and the working command (`--target <owner>`). Two scope cases: a `project` receipt met by a `user` request is refused `installer.owner.mismatch` without building an owner root (the receipt records no project); a `user` receipt met by a `project` request builds the owner root from the request's home and ignores the request's project. `--project-dir` is ignored for user scope in both installers (Python must not resolve it).
4. Project scope only: the folder is not inside the project directory: refuse `installer.project.escape`. Message names the project and the folder. Both sides are canonicalised the same way, Node `fs.realpathSync.native` and Python `Path.resolve()`, on the project directory and on the folder; strip a `\\?\` prefix; compare with `path.relative` / `relative_to`, never a string prefix (so `p2` is not inside `p`); compare case-insensitively on win32 only. A path that does not exist yet is not compared (step 1 already returned). A project whose `.claude` is a link out of the project is refused by design (R65 (2)).

`codex` and `generic-agents` share a root so they pass step 3; `~/.claude/skills` linked to `~/.agents/skills` makes the second target fail step 3 (R66).

### Codes and reporting

Codes follow the `area.thing.state` shape of `atoms.span.mismatch` in `scripts/verification_findings.py`: `installer.owner.mismatch`, `installer.project.escape`, `installer.receipt.owner_invalid`, and for #27 `installer.receipt.missing`. The installers have no codes today; these are the first.

Reporting, `--json`, identical in both installers: exit 2, nothing changed on disk, and a payload with at least `state: "failed"`, `code`, `error` (human text, wording not pinned). `verify` also carries `passed: false`. `code` is omitted from the payload when the error has none, in both installers. Plain output is the existing format; Python prints the extra `code:` line. The tests compare exit code, `state`, `code`, `passed`, and that disk is unchanged; not `error`, except the named-substring checks in the tables.

Error classes, produced by the guard slices and consumed by the recovery slices:

- Python: `InstallError(message, code=None)` in `installer/core.py`; the instance has a `code` attribute (`None` when absent). `command_install`, `command_verify` and `command_uninstall` in `installer/install.py` put `code` in every `InstallError` payload.
- Node: `new InstallerError(message, code)` in `installer/node/manifest.js`; `error.code` is `undefined` when absent. The catch in `run()` in `installer/node/cli.js` puts it in the payload.

### Recovery text (#27, R71, R79)

Appended to the two core refusals ("existing target is unmanaged; installation receipt missing", Node "installation receipt missing; refusing unmanaged operation", Python "...refusing unmanaged uninstall"), code `installer.receipt.missing`: say the folder has no receipt, likely replaced by `npx skills add`. The message keeps its first words (`tests/installer/test_install_mutations.py` matches the "receipt missing" substring unedited).

The hint maps `claude` to `claude-code` and `codex` to `codex`: for those it gives `npx skills remove deeper-reading -g -a <agent> -y` (omit `-g` for project scope) and says a shared `.agents` folder may belong to more than one agent, so `remove` must list each agent (`-a claude-code codex`). Any other target gets the delete route only. Delete wording, also used in the owner_invalid message and the README: "delete the skill folder `deeper-reading` for each agent; if it is a link, remove the link itself and not its contents; never delete only the shared `.agents` folder; then run `install` for each agent." A refusal may shorten it only if it keeps the link sentence, which is the substring `remove the link itself`.

### Shared case tables

Two JSON files, read by both runtimes, the way `tests/fixtures/host-resolution-cases.json` is read by `tests/installer/test_discovery.py` and `tests/node/discovery.test.js`. Both are frozen by A1; `installer-ownership-cases.json` is run by A2 and A3, `installer-recovery-cases.json` by A4 and A5:

- `tests/fixtures/installer-ownership-cases.json`.
- `tests/fixtures/installer-recovery-cases.json`.

Shape, the same in both: an object with a `cases` array. Each case is `{"id": <string>, "steps": [...]}`, ids unique. Step kinds:

- `{"do": "mkdir", "path": P}`.
- `{"do": "link", "at": P, "to": P}`: create parent folders of `at`, then a link (junction or directory symlink, see Global Constraints).
- `{"do": "file", "path": P}`: create a file with some content (an unmanaged folder has no receipt).
- `{"do": "receipt", "path": P, "delete": [key...]}` or `{"do": "receipt", "path": P, "set": {key: value}}`: edit the JSON object in `P/.install-receipt.json` written by an earlier `run`.
- `{"do": "run", "cwd": P, "home": P (optional), "args": [...], "expect": {...}, "unchanged": bool, "survives": [P...] (optional)}`: run the installer with `--json` appended, `HOME` and `USERPROFILE` set to `home` (default `{home}`), cwd `cwd`. `expect` holds `exit`, `state` and, when the call fails, `code`; `passed` for a `verify` refusal; `message_has` and `message_lacks`, lists of substrings of the `error` text (only the ones the tables name). `unchanged: true` means the file tree (paths and bytes) under `{work}` is identical before and after the call; links are recorded as a link plus its target text and are not followed, and a path under a link is compared at its own real path. `survives` lists paths that must still exist after it.

Paths and `args` may use `{work}` (the case's temp folder), `{home}` (`{work}/home`) and `{project}` (`{work}/project`). A reader replays every step of a case in a fresh `{work}` against its own installer only (`python installer/install.py` in A2/A4, `node installer/node/cli.js` in A3/A5), so Python and Node meet the same `expect`. A reader raises on an unknown `do` or an unknown key in a step or in `expect`, so a field it does not implement cannot pass vacuously.

These substrings are the only message assertions (`--target codex`, `skills remove`, `remove the link itself`); the codes are shared across targets, so the message carries the difference (R79). They are the one exception to AGENTS.md line 313 and a reviewer must not strip them.
