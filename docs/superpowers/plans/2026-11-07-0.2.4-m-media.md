## 1. Goal and rows closed

Make images, SVG and diagrams in Markdown, HTML and DOCX visible. Each extractor records the references
listed in F2; format QA gives each one a disposition (read with a host vision tool, or not read with a
reason); the verifier enforces it; TRAVERSAL_REPORT.md lists them. Honest claim: a disposition records
that the agent read the media or said why not. The verifier does not prove the media was understood.
A ledger `media` edit is caught only by the report byte-compare (an agent who re-renders the report
goes unnoticed); dispositions are agent-authored, the trust model of every ledger verdict.

Closes: L2-1, L2-2, L2-3 (audit-L2.md). D contains no word about media; M adds every media sentence,
including README and CONTRIBUTING.

## 3. Frozen interfaces

F1. Extractor recording. During packing a media reference lives in `Block.locator["media"]`, a list of
`{"kind","syntax","ref","alt"}` (ref and alt may be null). `chunk_common.MediaCollector` is the only way
extractors set it: `MediaCollector().add(position, kind, syntax, ref=None, alt=None)` where `position` is
`len(blocks)` when the reference is seen, and `.apply(blocks)` writes each entry to the first block with
non-empty text at or after `position` (past the end: the last such block). An image-only paragraph
attaches to the next block. No text is invented, so chunk text, ids and `content_sha256` do not change.
`pack_blocks` keeps `media` only on fragment 1 of a split block. `build_manifest` removes `media` from
every locator (top level and `locator.blocks[*]`) and builds F2. A source whose only content is media
has no text and fails A's empty-extraction guard (R10); M keeps that guard first.

F2. Manifest. Optional top-level `media` list, present only when non-empty (no-media manifests and
reports stay byte-identical). Entry fields in this order: `id` ("media-0001", 1-based, manifest order
then position order), `chunk_id`, `kind`, `syntax`, `ref`, `alt`. `ref` is the src, href or target,
capped at 200 chars (data: URIs keep only `data:<mime>`); `alt` is whitespace-collapsed, capped at 200.
`schema_version` stays 1. The verifier re-extracts and compares whole manifests, so `media` is covered
by the existing `reproduction.mismatch` check. `chunk_id` is the first chunk of the nearest following block.

kind: `image`, `svg`, `diagram`, `embedded`. syntax by extractor:
- Markdown: `md_image` (`![a](p)` and `![a][id]`; ref is the label for the reference form), `md_link`
  (inline link whose target, ignoring a query or fragment, ends .png .jpg .jpeg .gif .webp .bmp .svg),
  `html_img`, `html_svg` (outermost `<svg`), `html_diagram` (raw `<pre>` or `<div>` whose class has a
  `mermaid` token; kind diagram, ref null), `fence_diagram` (fence info string mermaid, plantuml, dot,
  graphviz or d2; kind diagram, ref null). Inline code spans are ignored. Other fenced code is not scanned.
- HTML: `img` (src, else data-src; alt), `svg` (outermost), `object` and `embed` (data or src; kind
  image when type or extension is an image, else embedded), `diagram` (outermost `pre` or `div` whose
  class has a `mermaid` token; kind diagram, ref and alt null; its source text stays in the chunk as
  today). Inside script, style, noscript, template: ignored. Inside tables and `pre`: recorded.
- DOCX: `drawing` (`w:drawing` holding a blip, chart or diagram; ref is the target of `a:blip@r:embed`,
  else `@r:link`, else the chart or diagram relationship; alt is `wp:docPr@descr`, else `@title`; kind
  diagram for chart or diagram data; a picture-less text box or shape is not recorded, its text is
  already extracted), `vml_image` (`w:pict` with `v:imagedata`; ref is the `r:id` target),
  `ole_object` (`w:object`; ref is the `o:OLEObject r:id` target; kind embedded). Targets come from the
  part's own `word/_rels/<part>.xml.rels`. Every story part is walked (body, table cells, headers,
  footers, footnotes). `mc:AlternateContent`: Choice only, Fallback never read (A's rule), so one
  picture is recorded once. O7 markers untouched.

F3. Ledger. Top-level `media` list next to `entries` in the chunk evidence ledger (schema stays v2).
Entry: `{"id","disposition":"read","tool":"<host vision tool>","summary":"<what it shows>"}` or
`{"id","disposition":"not_read","reason":"<why>"}`. The draft given to `build_evidence.py` carries the
same top-level `media` list. The builder checks it against the manifest, copies it, and fails without
writing on a problem. The ledger omits `media` when the manifest has none, even if the draft has
`media: []` (old drafts and old ledgers stay byte-identical). The ledger is bound to the manifest hash,
so a changed manifest stales the dispositions.

F4. In `chunk_common.py` (no new shipped file): `manifest_media(manifest) -> list[dict]` (empty when
the key is absent) and `check_dispositions(media, dispositions) -> list[tuple[code, message, detail]]`.
`build_evidence.py` raises `EvidenceBindingError` on the first item; `verify_run.py` wraps each item in
a `Finding`. The rules live once. `detail` is the media id, or `media[<index>]` when an entry has none.

F5. Finding codes, all on predicate `format_qa_complete`: `media.disposition.missing` (manifest id with
no disposition), `media.disposition.unknown` (id not in the manifest), `media.disposition.duplicate`,
`media.disposition.invalid` (dispositions not a list, entry not an object, disposition not read or
not_read, `read` without non-empty `tool` and `summary`, `not_read` without non-empty `reason`).

F6. `render_traversal_report(manifest, ledger)` keeps its signature and, for manifests without media,
its exact output. With media it adds after "Run summary": `Media references: N`, `Media read: R`,
`Media not read: U`, `Media without disposition: M`, then a `## Media` table with header
`| Media | Chunk | Kind | Syntax | Reference | Alt | Disposition | Tool or reason |` (Disposition is
`read`, `not_read` or `missing`) and one sentence: Chunk is the first chunk of the nearest following
block, and the coverage above is of extracted text only. `traversal_report.py` is unchanged.

F7. `inspect_chunks.py`: the chunk detail view prints one line per media entry of that chunk
(`media-0001 image md_image diagram.png alt: ...`); `--summary` appends `media:N`. `chunk_view`
functions take an optional `media` list; callers that omit it behave as before. The agent learns media
ids before the ledger exists.
