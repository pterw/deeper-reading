## 3. Frozen interfaces

F1. Documented worked run, in `references/evidence.md` under the heading `## Worked first run`. Fences
are found by info string (first word `text`/`json`/`sh`/`markdown`, then the label):
`markdown source.md` (the one-chunk source), `sh first-run` (extract, then `build_evidence.py`, then
`traversal_report.py`; placeholders `<run-root>`, `<source>`, `<source-uri>`), `sh verify` (the
`verify_run.py` command, run last), `sh sha256` (one Python `hashlib` one-liner with `<file>`, run for the
source and the manifest; no `sha256sum`, which PowerShell lacks), `json run.json`, `json draft-evidence.json`. Placeholders: `<SOURCE_PATH>`, `<SOURCE_SHA256>`,
`<MANIFEST_SHA256>`, `<CHUNK_ID>`, `<CHUNK_SHA256>`. The prose beside them states: the 8 files named in
`evidence` must exist (the builder and report script create two, the agent writes the other six); the
two shas come from the `sha256` command; `<CHUNK_ID>` and `<CHUNK_SHA256>` are `chunks[0].id` and
`.content_sha256` of the manifest; the event triple and one `plan.nodes` entry repeat for every chunk.
F2. Preflight receipts layout (evidence.md, "Skill preflight receipts"): a Markdown table with the
columns `Reference path`, `Required gate`, `Completed`; human-audited, no machine parse. Pinned phrases
stay (`test_phase_gated_loading.py`, `test_anti_skimming_docs.py`).
F3. Proof classes (definition-of-done.md): a short list of what the agent records and the verifier only
checks for existence (`skill-preflight.md` rows, `failure-ledger.md` and `verification-log.txt` content,
`format-qa.md` content). `prerequisites.md` carries the same correction, with a link, not a copy.
F4. USAGE heading `## Skill roots` (target-by-scope table); README links to it.
F5. Changelog: PR D adds lines under `## Unreleased`, opening it at the top if absent, else appending
(R13). It never edits the 0.2.3 section.
