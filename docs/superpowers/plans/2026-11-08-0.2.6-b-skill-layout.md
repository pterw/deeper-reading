# Plan B: 0.2.6 skill layout (#28) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the skill payload into `skills/deeper-reading/` so `npx skills add` copies 38 files (313 KB), not 175 (1,612 KB), and finds one skill. The installed tree, the receipt hash keys and the installed paths do not change. Both installers find the payload through one manifest field, `skill.root`. Closes #28.

**Architecture:** Base is plan A's PR head; branch `refactor/skill-layout`, cut from A's head (R64 stack: keywords PR, A, B, C). Then one move commit carries the rename, the ship lists and the test path edits; its test edits are sliced into parallel code phases by disjoint test groups, and the group lands as ONE commit. Prose and the changelog follow.

**Tech Stack:** Python 3.13 standard library, pytest, Node 20+ with `node --test`, git, `npm pack`.

## Frozen Interfaces

- F1 Manifest field: `skill.root`, a POSIX path relative to the package root, optional, default `"."`. Real value `"skills/deeper-reading"`. `payload` entries stay exactly as today and are relative to the skill root, so `payload_hashes` keys and the installed tree are byte-for-byte what 0.2.5 installs.
- F2 Resolution, one function per installer: Python `skill_root(manifest_data, package_root) -> Path` in `installer/manifest.py`; Node `skillRoot(manifest, packageRoot)` in `installer/node/manifest.js`. Both return the resolved folder. `payload_files`, `payload_hashes`, `_copy_payload`/`copyPayload` and the receipt `version` (`VERSION`) all read from the skill root. `package_root` stays the repository/package root everywhere else: `MANIFEST.json`, `installer/`, `package.json` and the `PACKAGE_ROOT` constants do not move.
- F3 `document_profile_status(profile, *, skill_root=...)` (Python) and `documentProfileStatus(profile, {skillRoot})` (Node) replace the `package_root`/`packageRoot` option; the default is `skill_root` of the real manifest. Callers `install.py` and `cli.js` pass the resolved skill root.
- F4 Readers of the field: the two functions in F2 and `tools/release_check.py` (reads `MANIFEST.json` directly, default `"."`, so its synthetic-root tests are unchanged). Tests do not read it (F5). `release.yml` uses the literal path `skills/deeper-reading/VERSION` (3 sites) in the move commit. `distribution.py` builds the zip from the package root; its `SKILL.md` guard follows the field and keeps `"."` when no `MANIFEST.json` exists (synthetic tests).
- F5 Test layout helper (R80): `tests/layout.py` exports `ROOT` and the fixed constant `SKILL_ROOT = ROOT / "skills" / "deeper-reading"`; `tests/node/helpers.js` exports the same constant. Neither reads the manifest, so tests state the intended layout. A root `conftest.py` puts `SKILL_ROOT` and `tests/` on `sys.path`. All three arrive in the move task; the tasks before it do not use them.
- F6 Ship lists after the move: `package.json` files = `LICENSE`, `MANIFEST.json`, `README.md`, `installer/node`, `skills/deeper-reading`, plus the two `!` exclusions. `RELEASE_FILES` loses `SKILL.md` and `VERSION`; `RELEASE_DIRECTORIES` loses `references` and `scripts` (`skills` now holds them). The root `LICENSE` stays; the copy at `skills/deeper-reading/LICENSE` is a real file (never a link), asserted byte-equal by a test.
- F7 Installed-tree pin (R82): `tests/fixtures/installed-files-0.2.5.json`, the sorted 38 relative paths, a record of 0.2.5. Generated from `git archive v0.2.5` (the tag exists) installed with the 0.2.5 installer; never edited, never regenerated from the new tree. Both installers' tests install the real package into a throwaway target and compare the file list (receipt excluded) to it; the Python test also compares the receipt's `payload_hashes` keys to it. Command: `git archive v0.2.5 | tar -x -C <scratch>`, then `python <scratch>/installer/install.py install --target generic-agents --scope project --project-dir <empty dir> --json`; the fixture is the sorted list of files under `<empty dir>/.agents/skills/deeper-reading/`, relative to that folder, minus `.install-receipt.json` (38 paths). The commit body records this command. Plan C adds `installed-files-0.2.6.json` for its own changes.
- F8 Error wording, frozen so the Python and Node tasks agree without reading each other. `validate_manifest`/`validateManifest` append exactly these strings: `skill.root must be a string` (not a string); `skill.root must be a relative path` (absolute); `skill.root must not contain ..` (a `..` segment); `skill.root is outside the package root` (resolves outside, including through a link); and, when the resolved folder has no `SKILL.md`, the existing text `Missing canonical SKILL.md at package root` unchanged, so no existing assertion changes. One value produces one error, the first that applies in the order listed (string, absolute, `..`, outside, no SKILL.md). `skill.root` of `""`, containing a backslash, or starting with a drive letter (`C:`) is refused with `skill.root must be a relative path`; an explicit `"."` is the same as an absent field; a `skill.root` that resolves to a file reports `Missing canonical SKILL.md at package root`. `tools/release_check.py` reports a failure line (exit 1) for a `skill.root` that is not a string, is absolute, has a `..` segment or resolves outside the root, and never falls back to `"."` for a field that is present and bad.
- F9 Landing groups. Group "skill-root" = B1, B2, B3, B4, B20, one commit. Group "move" = B8-B15, one commit. Group "prose" = B16-B18, one commit. Each slice has its own review; the controller applies a group's reviewed patches together.
