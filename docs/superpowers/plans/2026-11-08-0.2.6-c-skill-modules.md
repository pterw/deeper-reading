# Plan C: modules, references and description (#29) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #29. Codex lists the six internal modules as separate skills because it collects every file named `SKILL.md` up to depth 6 (Codex 0.164.0-alpha.11.1 lists 7 skills before and 1 after the modules are renamed). After this plan no module is named `SKILL.md`; module references resolve from the skill root; the description says what the skill does and when to use it (at most 1,024 characters); `skills-ref validate` runs in CI. This is the one PR that changes installed paths.

**Architecture:** Branch `fix/skill-modules`, cut from plan B's PR head. Paths below are repository paths at that head: the skill root is `skills/deeper-reading/` (the folder holding `SKILL.md`, found by `skill.root` in `MANIFEST.json`). Tests use `SKILL_ROOT` from `tests/layout.py` and `tests/node/helpers.js` (a fixed constant); installer tests locate the root of a copied package with `skill_root(manifest.data, package)` (Python) and `skillRoot(manifest, packageRoot)` (Node). Design choices: (1) the folder is renamed as well as the files, `skills/<name>/SKILL.md` becomes `modules/<name>.md`, because a folder named `skills/` inside a skill is the shape recursive scanners look for and it is confusing next to the repository-level `skills/`; flat files also drop six directories and the `name:` frontmatter that makes a file look like a skill; (2) module files drop their YAML frontmatter (a module is not a skill); (3) upgrade removal needs no new code, because both installers already delete files the old receipt owns and the new manifest does not (`installer/core.py` `_prune_owned_files`, Node `pruneOwnedFiles`, empty directories removed), so the plan adds tests only. The work is sliced into twelve tasks: one rename task (the six modules, the root router and the prerequisites line are one change), one for the manifest and its fixture, one per test group, one for CI, one for prose, the CHANGELOG, and the hands-on check; tasks in a wave never share a file.

**Tech Stack:** Markdown skill files, Python 3.13 installer and pytest, Node installer and `node --test`, GitHub Actions, `skills-ref` 0.1.1.

Sections: Global Constraints=brief, Frozen Interfaces=brief, Not in scope=reference, Dispatch=reference, Tasks=reference, Risks and open questions=reference
