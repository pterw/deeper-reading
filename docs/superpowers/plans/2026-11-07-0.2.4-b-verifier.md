Verifier semantics after B1: let `cut = index of the last done event, else len(events)`.

(`done.failure.unresolved`) are evaluated over `events[:cut]` with or without `done`.
`done.verification_started.missing`, `done.verification_passed.missing`,
`done.verification.stale` stay gated on a `done` event (V2: the verifier runs before
`verification_passed`/`done` exist). A ledger with no `done`, valid otherwise, yields no
findings. The message text of the two codes may be reworded; code and predicate may not.

CLI after B4: any exception inside `validate_findings` (not only
`TypeError/ValueError/OSError/RecursionError`) yields `ledger.validation.error`, so
`main()` always rewrites `dod.json` (`passed: false`) before exit 1.
