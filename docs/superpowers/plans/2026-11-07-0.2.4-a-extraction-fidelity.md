## 3. Frozen interfaces

Consumed by later PRs (D adds media records to these same three extractors, and
documents the markers):

1. DOCX tracked-change markers (O7), in chunk content, exactly:
   `[deleted: <text>]` for the text of a `w:del` element and `[inserted: <text>]` for a
   `w:ins` element, `<text>` stripped of leading and trailing whitespace, markers
   emitted only when `<text>` is non-empty, one marker per `w:del`/`w:ins` element.
   Field instructions (`w:instrText`) are never emitted. `mc:Fallback` subtrees are
   never read; `mc:Choice` is.
2. Empty-extraction guard (R10): `chunk_common.build_manifest` raises `ValueError`
   when the concatenated content of all `packed_chunks`, with all whitespace removed,
   is empty. It tests total text, not chunk count (the PDF extractor emits
   empty-content chunks for empty pages). It applies to every `source_format`
   (`markdown`, `html`, `docx`, `pdf`), including an empty or whitespace-only source.
   The message names the format and contains `no extractable text`
   (`<format>: no extractable text`); for `pdf` it also says OCR is needed and
   points at the `oai-native` profile. The CLI boundary (`script_io.run_cli`) turns it
   into `FAIL: ValueError: ...` on stderr, exit code 1, and no manifest file written.
   No verifier finding code is added or frozen. D's media work must keep this guard.
3. Atomic Markdown blocks (fenced code, table) end with exactly one `\n` in chunk
   content, so the extracted text stream never glues two chunks (L2-4). Existing
   chunk ids and hashes change for any source containing a fence or table; nothing
   persists across runs, so this is not a migration.
4. Markdown `heading_path` entries keep a trailing `#` when it is part of the title
   (`## Using C#` gives `Using C#`); only a closing run preceded by whitespace is
   stripped.
5. HTML: block-level and line-break tags separate text, so chunk text for
   `<p>a<br>b</p>` contains `a` and `b` as separate whitespace-delimited words.

Test helpers shared by all tasks: `run_extractor` and `assert_manifest_integrity`
already in `tests/test_extractors.py` (reuse, do not copy).

### A1 Fix HTML heading loss, cell word merge and fused lines (T2-01, T2-02, T2-03, C1-03)

Wave 1. Touches: `scripts/extract_html.py`, `tests/test_extractors.py`. After: none.
Mode: code. No hash-pinned test changes (section 3).

Behaviour, in `StructuralHTMLParser`:
- An open heading is closed implicitly (its text emitted as a heading block, the
  heading path updated) on any heading end tag (matching or not), on end of input
  (`finish()`), and, only once the heading already holds non-blank text, on another
  heading start tag or a start or end tag from `FLOW_BOUNDARY_TAGS`, `table` or `pre`.
  A boundary tag before any heading text leaves the heading open, so
  `<h1><div>Title</div></h1>` keeps "Title" as the heading. Text after the heading then
  flows as body.
- Table cell text keeps the spaces between text nodes. Collect text per cell and
  normalise whitespace once when the cell ends, instead of cleaning each text node. A
  cell ends at its `td`/`th` end tag, at the next `td`/`th` start, at `tr` end or at
  `table` end, whichever comes first, so a cell with an omitted end tag keeps its text.
  Text outside any cell (a `caption`, text directly in a table or row) keeps going to
  the row, flushed as its own space-separated item so it never glues to a cell. A nested table's cells flush to their own buffer; `br` and `input`
  between cells add nothing (only whitespace, removed at normalisation).
- `br` appends one space to whichever text buffer is active (flow, heading or cell);
  it does not split a block.
- `hr`, `details` and `summary` join `FLOW_BOUNDARY_TAGS` (`hr` matters only inside one
  block, `<div>a<hr>b</div>`). `input` appends a space to the active buffer, like `br`
  (the verified `<form>Name<input>Value</form>` is fused by `input`, not by `form`).

Acceptance:
1. New failing-first test, parametrized over the verified inputs, asserts the joined
   chunk text contains every expected phrase: `<h1>Only title unclosed<p>All the body
   text</p>` gives "Only title unclosed" and "All the body text" (today: zero
   chunks); `<h1>Alpha intro<h2>Beta</h2><p>Body</p>` keeps "Alpha intro";
   `<h3>Closed with wrong</h4><p>b</p>`; `<div><h1>T</div>text` gives heading "T" and
   body "text"; control case `<h1><div>Title</div></h1><p>b</p>` gives heading
   "Title" and body "b" with `heading_path == ["Title"]` (passes today; must still
   pass); control case `<table><caption>Cap</caption><tr><td>a<td>b</tr></table>`
   gives "Cap", "a" and "b" as separate words (today "Cap" glues to the first cell, so
   this case is failing-first; A5's token-coverage cases include this table shape); `<td>one <b>two</b> three</td>` gives "one two three";
   `<p>line one<br>line two</p>` gives "line one" and "line two" as separate words;
   `<h1>Ti<br>tle</h1>` gives "Ti tle"; `<details><summary>Sum</summary>Detail text
   </details>` and `<div>a<hr>b</div>` give separate words; `<form>Name<input>Value
   </form>` gives "Name" and "Value" separate. Run on the base tree it fails on each
   case; after the fix it passes.
2. `python -m pytest tests/test_extractors.py tests/test_mutations.py -q` exits 0.
3. Control cases stay unchanged: `<p>A<span>B</span></p>` gives `AB`; `<p>The<wbr>word</p>`
   gives `Theword`. Asserted in the same parametrized test.

### A3 Fix Markdown stream gluing, short tables, fence closer, `C#` heading (L2-4..L2-7)

Wave 3. Touches: `scripts/extract_markdown.py`, `tests/test_extractors.py`. After: A2.
Mode: code. No hash-pinned test changes.

Behaviour, in `parse_markdown_blocks`:
- Fenced and table blocks end with one `\n` (section 3 item 3) rather than the
  stripped end.
- `TABLE_SEP_RE` accepts one or more dashes per cell and one column, but the
  separator row must contain a `|` (so a `---` thematic break or setext underline
  under a line containing a pipe is not a table).
- A fence closes only on a line that is the opening marker character, at least as
  long as the opener, followed by nothing but whitespace.
- Heading titles lose only a closing `#` run that follows whitespace.

Acceptance (failing-first, one parametrized test over inputs, assertions on the parsed
blocks through the CLI helper):
1. "```\ncode\n```js\nmore code\n```\nafter\n": the fence is one block containing
   "more code"; "after" is a text block.
2. `| a |\n|-|\n| 1 |\n` and `| a | b |\n|--|--|\n| 1 | 2 |\n` give one `table` chunk;
   `a|b\n---\n` does not.
3. `## Using C#` gives `heading_path == ["Using C#"]`; `## Title ##` gives `["Title"]`.
4. For a source with a fence directly followed by a table and a heading, the
   concatenation of chunk contents has the fence closer, the table header and the

5. `python -m pytest tests/test_extractors.py -q` exits 0 (this includes the existing

### A5 Word-coverage test across Markdown, HTML and DOCX

Wave 4. Touches: `tests/test_extractors.py`. After: A1, A2, A3, A4. Mode: serial.
No hash-pinned test changes.

Behaviour: one parametrized test (one case per format) built from the fixture
constants of A1-A3. Hard shapes: cell markup, `br`, unclosed heading, a table with a
`caption` and an unclosed `td` (`Cap`, `a`, `b` as separate words), text box, a
Markdown table whose last row ends in a word (no trailing pipe) directly before a text
block (`a | b\n-|-\n1 | 2\n` then `Next`; a lost newline reads `2Next`), CJK/emoji
word. Expected words (`\w+` runs) are listed per case. The test extracts with the CLI
helper, removes the marker words `deleted` and `inserted` (DOCX only) and asserts the
multiset of chunk words equals the expected one (fails on a lost, merged or duplicated
word). Fence glue does not change a `\w+` multiset; A3's acceptance 4 covers it.

Acceptance:
1. `python -m pytest tests/test_extractors.py -q -k word_coverage` passes with three
   cases.
2. Mutation check recorded in the commit body: with A1's cell-text fix reverted the
   HTML case fails; with A2's `mc:Fallback` skip reverted the DOCX case fails; with
   A3's table-row newline (the table path, not the fence path) reverted the Markdown
   case fails (each reverted by hand in a scratch copy outside the repo, then
   discarded).
3. The test file adds no helper that duplicates `run_extractor` or
